# Runtime notes

- Connected usage/composer geometry shares the existing 22px radius through one CSS token. A non-interactive two-corner gradient joins the surfaces without painting across the input or changing its geometry. In the 1.9.1 candidate the existing row is inserted immediately before the composer body inside the enclosing layout, including nested wrappers. Toolbar order, Home/dispose and subscription identity are retained; no extra wrapper, runtime observer, timer, forced scroll or layout read is added. A self-owned 16-case Chrome ResizeObserver model validates the height-reservation contract and retained reader position, not official internal measurement or actual route acceptance.

- The portable MCP command must be `./plugin/launch-macos.sh`, not an absolute interpreter path. Codex skips invalid individual server declarations while retaining skills, which can make a broken plugin look installed. The launcher has its own shebang and 755 mode; the regression executes the manifest itself. See the in-app guide for pinned spec/parser evidence and actual host acceptance limits.

- 1.9.4 retains `mcp.json` → verified bundled Node → self-contained MCP server and versioned HTML UI. The global `xskin_open {}` entrypoint carries official `openai/ui` metadata; the remaining ten tools are app-only. Strict inputs never accept commands or arbitrary paths. Private state and 64-hex session capabilities stay in `_meta`. `xskin_read_media` returns at most 512 KiB per request after file-identity checks; the UI builds local Blobs. Preview CSP allows Blob media and no external connect origin. There is no HTTP preview server or preview port; this does not remove the separate background engine's loopback CDP connection.
- Original filenames remain in saved/pending metadata. Optional preview failure cannot undo a completed import or Apply result. Native chooser cancellation retains prior media; stale selection IDs require reselection. Refresh only reads state; explicit `xskin_recover {}` runs the existing interrupted-transaction recovery while other edits remain disabled. A transport timeout/loss refreshes once and offers status retry instead of repeating an uncertain mutation.
- Confirmed Apply/mask dispatch does not impose the adapter's shorter outer process timeout over the existing separately bounded backend forward/rollback phases. Other limits remain. A proportionally scaled regression reproduces the previous timeout interrupting restoration. The 96 MiB sparse MP4 fixture proves import/state handling, not actual codec playback.
- 1.9.2 draws applied original media in a fixed, non-interactive layer inside the iframe, independently of an opaque outer host canvas. Pending media only affects Preview until Apply. Matching active/preview media share one Blob; differing media use at most two. Background video stops while hidden, paused or under Reduce Motion; video previews remain paused until the user plays them. Original 4K60 bytes are retained without transcoding; the own-video diagnostic reports frames/drops and an existing-interval playback sample. A 5.48-second local Codex/Dot sample measured approximately 59.1 presented FPS and zero additional dropped frames at 3840×2160; this is not sustained playback or display scan-out acceptance.
- The 1.9.4 body caps its iframe viewport by the host's valid height/maxHeight. Partial updates retain the cap; explicit unbounded/invalid dimensions clear it. This fixes the own model where iframe900/host680 produced main.bottom804 instead of584. Keep the 96px fallback and supplied safe insets; neither proves the height of an unknown desktop input. Main scrolls at the viewport edge with a thin transparent track while preserving the existing content width and working 16:9 preview. Errors take their own message height inside that stage, without an inactive-player hint.
- The 1.9.4 cross-origin opaque-canvas fixture passes 204 layouts / 720 scroll positions across reported/zero/absent safe areas, fixed/max host height, oversized iframe, narrow large text and failed previews. Image and real MP4 Apply change active tokens while retaining the original preview/background Blob and adding zero media reads. A 77.6 MiB synthetic original is read once in 156 chunks; exact confirmed selection/identity checks prevent unrelated promotion. Backend reads revalidate the media revision. Original video bytes and quality remain unchanged.
- The backend retains atomic operations, existing-connection requirements and first-import behavior. Earlier 1.9.3 filename/preview confirmation was followed by post-Apply failures; after correction, the user confirmed the same video’s preview, background and bottom controls work after Apply in actual-host 1.9.4. Functional source `bdd6751` passed 67 plugin tests, the full macOS runner, [CI](https://github.com/timmyc07/Xskin/actions/runs/39955991318) and [Flutter/package CI](https://github.com/timmyc07/Xskin/actions/runs/39955991299); publication requires final-commit checks; those results are recorded in the pull request and release notes. Cold starts, complete Home/task routes, sustained playback and CDP/CSS authorization remain unconfirmed.

- 1.8.5 retains the latest valid plan from the same session when subsequent events omit it or report null. Its tooltip marks it as conversation history, not live account status; a never-provided plan stays explicitly unavailable. Cache-write zero is unconfirmed because the public upstream parser can default missing data to zero; the tooltip retains the source value. Missing write fields are never fabricated as zero, and reads/writes remain distinct. See https://github.com/timmyc07/Xskin/blob/v1.8.5/docs/usage-fields.md for pinned public-source evidence and validation limits.

- Reliability update: elapsed-time heartbeats survive clock rollback; repeated renderer probe/push failures reconnect only the Xskin socket. Failed reads and unacknowledged deliveries remain retryable. Thread guards, file limits and lifecycle fan behavior are retained.
- Direct entries initialize the runtime before reading state and repair a missing watcher on a verified connection. Runtime updates compare executable content as well as version; image media is excluded. Native transactions recover interrupted applies/mask changes, and legacy image loading validates before publishing under the operation lock. See the repository macOS reliability review for physical acceptance limits.

- Final release review removes duplicate parsed-tail reads while retaining first-line overlap and bounded buffers. Expected CSS revision matching runs inside the verification deadline, so a transient old stylesheet cannot finish verification early.


- Native-header follow-up: web `--bg-*` tokens do not cover native `--color-surface*` paint. Map both families, clear utility-header pseudo paint/blur and structural settings containers, and keep control/image colors. Verify reports the loaded CSS hash and visible header coverage; an absent header is untested, not proof of transparency. Official route visual checks remain pending.


- 1.8.3 recovers missing usage/limits/lifecycle independently in bounded reverse reads, then resumes incremental reads. An unidentified task has no row; missing records and host heartbeat loss have explicit states. Remount changes the stable serialized installation token once to trigger immediate resubscription.
- Shared semantic surfaces cover native/Work route-local dark/light/theme scopes. Main surfaces stay clear, cards/dialogs/menus use increasing tint, and floating panels retain their controls. The rules are scoped away from Dot and disappear with Pause; no per-message DOM scan is added. See the repository surface-materials report for validation limits.

- Discover the official `com.openai.codex` bundle on every launch; do not assume an upgrade keeps the same executable internals.
- Use `Contents/Resources/cua_node/bin/node` from that bundle. Require Node.js 20+, a valid strict code signature, matching architecture, and OpenAI Team ID `2DC432GLL2` on both app and runtime.
- Do not ship a Node binary and do not depend on a globally installed `node` or `npm`.
- Launch the official app once through LaunchServices (`open -na`) with loopback CDP flags. Never retry by closing/reopening it when CDP readiness or verification fails.
- Prefer port `9341`; scan through `9441` on collision and record the selected port in state.
- Accept CDP only when the listener belongs to the discovered Codex main process or one of its legitimate descendants, the WebSocket URL is loopback-only, and an `app://` renderer exposes expected native shell markers.
- Treat loopback CDP as locally privileged but unauthenticated. Keep the themed session limited to trusted local use and close the port through a full Restore when finished.
- Poll page targets and reinject after document loads. A debounced mutation observer plus a low-frequency safety timer handles in-page route changes.
- Record injector PID, start time, executable, script path, app identity, selected port, and theme directory. Refuse to stop a PID when any required identity differs.
- Store mutable data under `~/Library/Application Support/CodexDreamSkinStudio`; keep the installed program under `~/.codex/codex-dream-skin-studio`.
- Back up and restore only `appearanceTheme` and `appearanceDarkCodeThemeId`. Leave `appearanceDarkChromeTheme` and unrelated TOML content untouched.
- Never modify, replace, unpack, repack, re-sign, or back up `app.asar`.

- 1.8.1 restores macOS official-app launches by explicit user choice. Its owned LaunchAgent observes new native launches and gracefully reopens each ordinary session once. The exact fresh PID/start time/executable/bundle/path/age are checked; the native helper only requests normal termination of that process. Refused quits are not forced, and managed relaunches/duplicate events cannot cause retry loops. Installation/login skips existing sessions.
- Pause retains the enabled service/preference and skips new launches until explicit Apply. Disable/Restore removes only the owned service. The optional ~/Applications/Codex (Xskin).app still starts directly without a reopen; direct clicks, automatic handoffs and Pause share its lock. Windows remains 1.8.0 shortcut-only with no automatic close/reopen.
- Upgrades migrate an enabled 1.8.0 shortcut preference into the native-launch service while retaining disabled/paused settings and saved media. A failed migration stops any new owned service and restores the previous runtime/service. New setup does not edit official apps or Dock pins.
- Replace/remove only a matching Xskin LaunchAgent. The existing shortcut-enabled marker stores the automatic-background preference independently of the paused session. Restore historical managed Dock pins during migration; pin optional direct entries with the normal system UI.
- The shared token reader/overlay includes draft IDs, stable serialized installation tokens, task lifecycle events, incremental long history and session-file creation tracking.
- 1.8.2 puts the usage strip before the native composer in normal flow, hides it on Home and clears pending data when unmounted. Composer/home-toolbar materials reveal the image or video without changing native toolbar geometry; narrow metrics wrap within their available width.
- CDP/CSS authorization remains unconfirmed. Official appearance/plugin documentation does not establish permission for renderer injection; see https://github.com/timmyc07/Xskin/blob/v1.8.3/docs/direct-launch-shortcut.md.

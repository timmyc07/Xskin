# Xskin

Open the plugin's `xskin_open` MCP App tool with an empty `{}` argument. It presents Xskin inside the host app. The same global entrypoint is available in the left navigation; the host controls whether it appears directly or under **More**. Never patch native menus or claim an exact position before verifying it.

Users choose a local image or MP4 with the system picker, inspect its in-app preview, and explicitly apply it. The panel also provides mask depth, automatic-start preference, Pause, Resume saved background, and English, Traditional Chinese, Simplified Chinese, and Japanese. Imports and previews do not apply a background. Do not call setting tools on the user's behalf merely to open the panel.

If `xskin_open` is unavailable, explain that the updated local plugin needs installation/reloading; see `docs/in-app-studio.md`. Do not substitute the standalone native window for the requested in-app panel. Only when explicitly requested, the separate native fallback remains `/bin/bash <plugin-root>/macos/scripts/open-background-studio.sh --json`; resolve the plugin root two levels above this skill, not the working directory.

Opening Xskin does not authorize background changes or Codex restarts. Embedded Apply, mask and Resume use an existing verified background connection; they never launch, quit or restart Codex. An ordinary session without that connection requires explicitly enabling automatic application, fully exiting and opening official Codex again for the authorized fresh-launch handoff before applying. The optional direct entry also stays ordinary while that preference is disabled or paused. Videos retain their original bytes, resolution, and frame rate; previews start paused. Source images are limited to 50 MiB and videos to 256 MiB. Media stays local; private filenames and preview URLs belong only in the panel, not chat. Do not modify the official Codex application, account, or model configuration.

Enabling **Apply when official Codex opens** installs a per-user service for the original official Codex app; the optional Codex (Xskin) entry starts directly without a reopen. Explain that each fresh ordinary official-app launch is gracefully reopened once to connect its background. Explicitly enabling the option authorizes those future handoffs; existing, paused and debugging sessions are skipped, quits are never forced, and duplicate/relaunch events are consumed without another handoff. Xskin can stay closed. Restore any previously managed Dock entry to the original official app. Pause retains the service/preference but blocks handoffs until explicit Apply or Resume; disabling the option or Restore stops the owned service. Never restart an already-open ordinary session without confirmation. Windows uses its managed shortcut and never automatically closes/reopens Codex. The official MCP App extension supports this panel entrypoint; it does not establish authorization for existing CDP/CSS backgrounds, which remains unconfirmed. See docs/in-app-studio.md and https://github.com/timmyc07/Xskin/blob/v1.8.4/docs/direct-launch-shortcut.md.
